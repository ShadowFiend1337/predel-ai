# SQL-анализ проверок решений

Версия 1.2, 16 сентября 2026 года. Этот раздел содержит семь запросов для PostgreSQL по первой выборке. Отдельный [блок сравнения продуктов](comparison/README.md) содержит ещё четыре запроса, модель связей и JOIN по второй выборке на 165 работ. Каждый файл содержит цель, описание результата и существенные ограничения.

## Источник и принятые определения

Структура основана на предоставленной [Google-таблице](https://docs.google.com/spreadsheets/d/1rLxt7ZERF11VZUILCKYxOf7WGRQ0GC2j2mJpLOH1cIg/edit?gid=0). В просмотренной выгрузке 9 042 строки: 8 902 по №13 и 140 по №14; `answer_id` и `ai_check_id` уникальны. Обнаружены одна неразбираемая дата отправки и 21 пропуск даты проверки куратора. Наблюдения подтверждены SQL-прогоном фиксированного снимка; [паспорт и результаты](../docs/15_dataset_analysis.md) содержат его SHA-256. Живая таблица при этом запуске повторно не читалась и может изменяться.

По уточнениям автора кейса от 16 сентября 2026 года `curator_points` используется как эталон, а `ai_points` и `ai_comment` относятся к модели «Стобалльного репетитора». Версия модели пока не предоставлена. Этот источник не отождествляется со [второй таблицей](../docs/21_product_comparison.md) на 165 строк с полями `PredelAI_score` / `true_score`: там эталон выставляла команда проекта, а данные двух продуктов сопоставлены внутри строки.

Гранулярность просмотренного набора — строка с ответом ученика, оценкой ИИ и оценкой куратора. Повторяющееся условие задачи не означает дубликат работы. При появлении повторов `answer_id` нужно проверить `ai_check_id`, время и происхождение записи до выбора правила учёта.

## Карта запросов

| Файл | Цель | Что показывает и как использовать |
|---|---|---|
| [01 — качество данных](01_data_quality.sql) | Найти записи, требующие уточнения | ID, баллы и даты проблемных строк; пропуски, недопустимый диапазон, обратный порядок времени. Строка с пропущенной датой может оставаться в сравнении баллов |
| [02 — повторяющиеся ответы](02_duplicate_answers.sql) | Предотвратить повторный учёт работы | `answer_id` и число строк с ним. Сначала определить причину повтора; запрос ничего не удаляет |
| [03 — состав выборки](03_sample_composition.sql) | Оценить представленность типов заданий | Число строк, разных задач и учеников по `task_number`. Общая точность при преобладании №13 преимущественно отражает этот тип |
| [04 — точность балла](04_score_accuracy.sql) | Измерить совпадение с эталоном | Число сравнений, точных совпадений, процент и среднее абсолютное отклонение в баллах по номеру задания. Соответствует M-QLT-01 и M-QLT-02 после фиксации источника оценок |
| [05 — направление расхождения](05_score_direction.sql) | Разделить завышения и занижения | Количество и доля каждой категории среди всех сравнимых работ, включая совпадения. Сумма округлённых долей может не равняться ровно 100% |
| [06 — сильные расхождения](06_largest_disagreements.sql) | Отобрать примеры для предметного разбора | До трёх работ каждого номера с максимальной абсолютной разницей и комментариями. Причину ошибки устанавливает эксперт; для подтверждения ложного замечания нужен разбор исходной работы |
| [07 — время до ручной проверки](07_review_duration.sql) | Оценить ожидание результата учеником | Число измерений, среднее, медиана и P90 в часах. Включает очередь; не показывает активное время куратора или время ответа ИИ |

## Подготовленная таблица

[00_checks_schema.sql](00_checks_schema.sql) создаёт временную `checks` в текущем подключении PostgreSQL. Все запросы явно обращаются к `pg_temp.checks`. Таблица исчезает при закрытии подключения; схема БД приложения не меняется. Это отдельный аналитический слой, а не существующая таблица `Attempt` и не миграция целевой ERD.

| Поля | Тип | Смысл |
|---|---|---|
| `source_row` | integer | Номер исходной строки для поиска дефекта; добавляется при подготовке |
| `answer_id`, `ai_check_id` | text | ID ответа и проверки ИИ; идентификаторы не участвуют в арифметике |
| `task_id`, `question_id` | text | ID задачи и вопроса исходной системы; связь с каталогом Predel требует отдельного сопоставления |
| `task_number` | integer | Номер задания ЕГЭ, в просмотренной выгрузке 13 или 14 |
| `stud_id` | text | ID ученика для подсчёта уникальных участников |
| `max_points`, `ai_points`, `curator_points` | numeric | Максимум, оценка ИИ и эталонная оценка; неизвестное значение — `NULL`, а не ноль |
| `ai_comment`, `curator_comment` | text | Комментарии сторон; HTML в исходном тексте не исполняется |
| `sent_to_review_at`, `curator_reviewed_at` | timestamp | Разобранные даты в одной согласованной временной зоне |
| `sent_to_review_at_raw`, `curator_reviewed_at_raw` | text | Неизменённые исходные значения дат, включая некорректные строки |

В учебной таблице намеренно нет первичного ключа и ограничений диапазона баллов: проверки 01/02 должны иметь возможность показать нарушения. Для рабочей нормализованной схемы ключи и ограничения задаются отдельно.

## Правила импорта и расчёта

1. Сохранить отдельный исходный снимок и его контрольную сумму в рабочем контуре; записать дату получения, лист и область выгрузки. Исходные работы, ссылки на фотографии и идентификаторы учеников в этот кейс не копируются.
2. Заголовки сопоставлять по названиям, а не по позиции. Поля `source_row` и `*_raw` добавляются при подготовке. Полную CSV с 36 колонками нельзя напрямую загрузить в эту сокращённую таблицу без сопоставления.
3. Пустые строки после удаления крайних пробелов превращать в `NULL`. ID сохранять строками. Числовые поля разбирать отдельно; недопустимое значение фиксировать в журнале импорта и оставлять `NULL`, не заменять нулём. `NaN` и бесконечности не считать допустимыми баллами.
4. Исходную строку даты сохранить в `*_raw`. Неразбираемое значение фиксировать в журнале и оставлять `NULL` в подготовленной колонке. Не угадывать дату по соседним строкам. Для расчёта времени подтвердить одну временную зону обеих колонок; приведённая схема хранит уже согласованные местные значения без зоны.
5. Выполнить 01/02 и согласовать обработку повторов и дефектов. Запросы 03–07 сами не удаляют дубли. Если повтор означает новый запуск ИИ, до расчёта выбрать единицу анализа и правило отбора запусков. Решение записать в протокол.
6. Для 04–06 нужны положительный максимум и два балла в пределах `[0; max_points]`. Пропуски дат этому сравнению не мешают. Для 07 нужны две даты и неотрицательный интервал; наличие баллов не является условием измерения времени.
7. Вместе с показателем записывать число исходных, включённых и исключённых строк с причинами. Нулевой балл является оценкой, `NULL` — отсутствием данных. Пустой результат запроса означает отсутствие подходящих строк, а не нулевую точность.

Подготовка CSV и SQL-прогон реализованы и выполнены на реальном снимке; [анализ](../docs/15_dataset_analysis.md), [протокол](../verification/dataset-analysis-report.json) и [команды повторного запуска](../tools/README.md). Автоматическое скачивание Google-таблицы не выполняется. Временные интервалы рассчитаны условно: часовой пояс и смысл событий пока не подтверждены. Ограничения учтены в [направлениях развития](../docs/16_product_roadmap.md).

## Учебный запуск

Использовать отдельное подключение PostgreSQL, например `psql` или SQL-редактор. Из корня кейса в одной сессии `psql`:

```text
\i sql/00_checks_schema.sql
\i sql/fixtures/synthetic_checks.sql
\i sql/01_data_quality.sql
\i sql/02_duplicate_answers.sql
\i sql/03_sample_composition.sql
\i sql/04_score_accuracy.sql
\i sql/05_score_direction.sql
\i sql/06_largest_disagreements.sql
\i sql/07_review_duration.sql
```

[Синтетические данные](fixtures/synthetic_checks.sql) содержат восемь вымышленных работ. Файлы 01–07 выполняют только чтение. Не загружать реальные строки поверх учебных: использовать новое подключение и пустую временную таблицу.

Ожидаемые результаты учебного набора:

| Запрос | Ожидание |
|---|---|
| 01 / 02 | Проблемных строк и повторов нет |
| 03 | №13: 5 работ, 2 задачи, 5 учеников; №14: 3 работы, 1 задача, 3 ученика |
| 04 | №13: 1 совпадение из 5, 20%, MAE 1,20; №14: 1 из 3, 33,33%, MAE 2,00 |
| 05 | Совпадение: 2 / 25%; завышение: 3 / 37,5%; занижение: 3 / 37,5% |
| 06 | №13: `demo-a4`, `demo-a5`, `demo-a2`; №14: `demo-a7`, `demo-a8` |
| 07 | №13: среднее 5 ч, медиана 5 ч, P90 8,2 ч; №14: 4 ч, 4 ч и 5,6 ч |

Результаты проверки файлов фиксируются в [протоколе SQL](../verification/sql-report.json). Учебные результаты не характеризуют качество PredelAI или ИИ исходной платформы.

Справочные определения: [агрегатные функции PostgreSQL](https://www.postgresql.org/docs/current/functions-aggregate.html), [оконные функции](https://www.postgresql.org/docs/current/functions-window.html).

# Контекст системы

## Реализация: внешняя граница

```mermaid
flowchart LR
    Student["Ученик"] <-->|"Отправка решения, получение результата"| Predel["PredelAI"]
    Predel <-->|"Распознавание и оценивание"| Provider["Внешние провайдеры языковых моделей"]
```

Сайт, API, компоненты проверки и БД входят в PredelAI. Провайдер моделей — внешняя зависимость. LMS и рабочее место куратора в действующую границу не включены.

## Реализация: внутреннее устройство

```mermaid
flowchart LR
    Web["Веб-приложение React"] <-->|"REST / JSON"| API["Сервер FastAPI"]
    API --> Check["Компоненты проверки в серверном процессе"]
    Check <-->|"Запросы моделей"| Providers["Внешние провайдеры"]
    API <-->|"Чтение и запись"| DB[("SQLite")]
    API --> Files["Хранилище исходных файлов"]
```

Компоненты проверки не изображаются отдельными микросервисами: это логическая декомпозиция внутри приложения.

## Целевая интеграция

```mermaid
flowchart LR
    LMS["LMS школы"] <-->|"Создание проверки и запрос результата"| Predel["PredelAI"]
    Curator["Куратор"] <-->|"Просмотр и утверждение оценки"| Predel
    Predel <-->|"Распознавание и оценивание"| Providers["Провайдеры моделей"]
```

Клиент LMS аутентифицируется отдельно; куратор имеет ролевой доступ. Детали очереди, хранения и повторной доставки раскрыты в архитектуре и диаграмме взаимодействия.

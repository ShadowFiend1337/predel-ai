# Протокол проверки API UC-01

Дата: 15 сентября 2026 года. Проверяются [описание API](11_api_specification.md) и его связь с [UC-01](03_use_case_text_submission.md). Итог: **38 HTTP-запросов и 74 проверки Postman пройдены** на изолированном стенде текущих обработчиков. Это подтверждение описанного текущего поведения, включая известные расхождения с целевыми требованиями.

## Основания и воспроизводимость

- [Машиночитаемый отчёт](../verification/uc01-api-report.json): дата и время, результаты каждого запроса, проверки, наблюдаемые поля и контрольные суммы.
- [Текущая коллекция](../postman/uc01-current.postman_collection.json): восемь групп P01–P08; 38 запросов включают подготовку стенда и проверку побочных действий.
- [Инструкция запуска](../tools/README.md): сборка, запуск стенда, Newman и формирование отчёта.
- [Снимок исходников](../contracts/source-snapshot.json): версия файлов приложения и отдельные ранее выполненные модульные тесты.

Источник — предоставленные обработчики приложения версии 0.3.3. Точное состояние фиксируется SHA-256, а не предполагаемым Git-коммитом. Проверки выполнены Newman 6.2.1. В отчёте записаны версии Python-библиотек. В выводе Newman было предупреждение Node.js об устаревшем `fs.F_OK`; проверкам оно не помешало.

## Условия стенда

HTTP-сервер доступен только на `127.0.0.1`. Используются реальные маршруты отправки и истории, схемы FastAPI, проверка подписи JWT и ограничитель частоты. Секрет JWT создаётся при запуске стенда; учебные токены живут два часа. Проверяются два синтетических ученика, `demo-a` и `demo-b`.

Задача `demo-ege13-001` и текст взяты из примера UC-01. Каталог и сохранение заменены объектами в памяти. Весь специализированный механизм оценивания заменён подготовленным результатом или управляемым исключением. Разбор шагов, отдельные оценщики, арбитр и математическое качество в этом запуске не проверяются. Статистика пользователя и начисление наград выключены.

`/_demo/session`, `/_demo/reset` и `/_demo/state` — служебные маршруты стенда. В API приложения их нет. Сброс перед каждой группой очищает попытки и ограничитель. Для P05 в окно ограничителя заранее помещаются 20 отметок запросов; следующий запрос проходит через настоящий ограничитель. Проверяется его срабатывание, а не нагрузочная производительность и не точность границы истечения 60 секунд.

## Выполненные сценарии

Ожидания текущего API взяты из кода до запуска. Целевой столбец — условия будущей приёмки, а не результаты HTTP-проверок v2. Успешная проверка известного дефекта не означает выполнение целевого требования.

| ID и связь с UC | Вход и ожидаемый текущий результат | Фактический результат | Целевой результат и статус |
|---|---|---|---|
| P01 — шаги 11–12; FR-014–FR-016, PAC-10 | Валидное решение; подготовленная оценка 2/2. HTTP-проверка v2 не выполнена |
| P02 — Е3; BR-003, LAC-IN-01, LAC-IN-02, LAC-IN-07 | Пустая/пробельная строка, отсутствие `task_id`, число вместо текста → 422 без оценивания/сохранения. Длинный текст принят, сохранено 39 999 символов после обрезания и удаления крайнего пробела | Превышение 40 000 → 422 без обрезания; GAP-01 подтверждён для длины. | P04 — Е4; FR-003, LAC-IN-04 | Неизвестный ID задачи → 404 без оценивания и сохранения | 404; счётчики 0/0 | Условие отказа подтверждено; целевой объект ошибки не реализован |
| P05 — Е2; FR-016, NFR-SEC-02 | После заполнения окна ограничителя → 429 без оценивания и сохранения | 429; счётчики 0/0 | v2 дополнительно требует `Retry-After`; целевая проверка подготовлена, не выполнена |

| P07 — представление результата А5/А7; FR-013, FR-P-003, PAC-P-01 | Подстановка предварительного результата 1/2 → 200, `needs_curator=true`, `is_solved=false`; поля `review` нет | Совпало; попытка сохранена. Наличие реальной задачи куратора не подтверждено | v2: `provisional` и ID сохранённой задачи куратора. Выбор ветви при реальном отказе оценщика здесь не проверялся |
| P08 — Е5/Е6; FR-011, FR-015, PAC-09 | Исключение оценивания → текущие 200 и ноль с признаком куратора. ## Подготовленная приёмка v2

[Целевая коллекция](../postman/uc01-target-v2.postman_collection.json) содержит восемь групп с ожидаемыми ответами C-11. Её нельзя запускать целиком на нынешнем стенде: маршруты v2 отсутствуют, а разные группы требуют разного состояния сервера.

Перед каждой группой будущий тестовый сервер должен быть подготовлен следующим образом:

| Группа | Подготовка |
|---|---|
| P01 | Задача и два отдельных ученика; допустимое решение даёт окончательный балл, история доступна |
| P02–P04 | Сброшенный ограничитель; валидный токен, кроме запроса P03; ID неизвестной задачи действительно отсутствует |
| P05 | Лимит тестового ученика исчерпан; сервер возвращает время ожидания |
| P06 | Действует предметное правило отсутствия хода решения |
| P07 | Один оценщик недоступен, второй возвращает пригодную оценку; сохранение попытки и задачи куратора доступно |
| P08, первый запрос | Нет пригодного результата оценивания и подтверждённой передачи куратору |
| P08, второй запрос | Оценивание доступно, сохранение достоверно откатывается; режим меняется перед этим запросом |

Указать `base_url`, `token`, `other_token`, `task_id` в окружении Postman; `other_token` принадлежит другому ученику. Сценарии выполняются по группам после нужной подготовки. Публичное тело запроса не управляет отказами сервера. Механизм подстановки отказов будущей реализации в данном кейсе не заявляется готовым.

## Что остаётся проверить после реализации

- Интерфейс UC-01: сохранение введённого текста, ожидание, защита от повторного нажатия и отсутствие автоматического POST после потери ответа.
- Е7: потеря ответа после фиксации и неопределённый исход сохранения. Проверка истории не должна подменяться утверждением, что запрос остановлен.
- Реальная БД: принадлежность попытки, согласованная фиксация попытки и задачи куратора, откат, уникальность ручной проверки, история изменений и конкуренция кураторов.
- Целевой API: все группы коллекции, неизвестные поля, границы длины, нулевой/полный/предварительный балл, смена результата после куратора, точные коды ошибок и состояния данных.
- Реальные этапы проверки, качество на размеченных работах, полное время обработки и нагрузка.

Эти пункты не входят в число 74 пройденных проверок. SQL-запросы и проверка на реальном датасете в данном этапе не выполнялись.

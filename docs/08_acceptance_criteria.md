# Критерии приёмки и стратегия проверки

Критерии описывают **целевое поведение**. Факт существования критерия не означает, что он уже пройден. Результаты проверок текущего кода и оставшиеся изменения приведены в [матрице реализации](20_implementation_status.md). Этот документ — единственный источник идентификаторов критериев приёмки.

## Сквозные критерии

| ID | Дано / когда | Ожидаемый результат |
|---|---|---|
| PAC-01 | Валидное решение задачи `ege13`, `ege14` или `ege15`; отправлен запрос | Выбран специализированный маршрут и установлен максимальный балл из конфигурации |
| PAC-02 | Валидное решение другого варианта | Выбран прежний механизм проверки |
| PAC-03 | Поддерживаемое читаемое изображение; извлечение успешно | Получена непустая запись и передана на проверку |
| PAC-04 | Запускаются оценщики A/B | Каждый получает общий предметный контекст и не получает ответ второго |
| PAC-05 | Модель вернула валидные критерии и допустимый числовой балл | Балл пересчитан по правилам; расхождение с числом модели сохраняется |
| PAC-06 | Валидные A/B вернули разные баллы | Арбитр вызван; причина вызова доступна в данных проверки |
| PAC-07 | A/B вернули одинаковый полный балл без существенной неопределённости | Арбитр пропущен; результат принят автоматически |
| PAC-08 | Один оценщик исчерпал попытки, второй успешен | Оценка второго сохранена как предварительная; назначена ручная проверка |
| PAC-09 | Оба оценщика недоступны и иного подтверждённого результата нет | Оценка отсутствует; опубликована контролируемая техническая ошибка; нет математического нуля и ложного сообщения о назначении куратора |
| PAC-10 | Проверка завершена и попытка сохранена | Ответ соответствует схеме и содержит согласованные баллы, пояснение и окончательность результата |
| PAC-11 | Полный балл, результат окончательный, ручная проверка не требуется | `is_solved=true`; во всех остальных случаях `false` |
| PAC-12 | Сохранение попытки не выполнено | Успешный ответ о сохранённой попытке не возвращается |
| PAC-13 | Сработала калибровка | Доступны ID и версия правила, баллы до/после, причина и изменение окончательности; при неприменимом условии изменения нет |
| PAC-14 | Имеется существенная OCR-неопределённость | Результат не окончательный; числовая оценка не заменяется техническим нулём |
| PAC-15 | Текст содержит ошибочную математическую формулу ученика | Исходный текст сохранён; математическая замена без подтверждения не выполняется |
| PAC-16 | Передан только итоговый ответ без необходимого хода решения | Предметный отказ объяснён; дублирующиеся поля балла согласованы; вызов ИИ не требуется |

Условия защиты общего результата, резервные действия и приоритеты проверяются по BR-005. Предварительные баллы разрешены только вместе с явной отметкой окончательности.

## Проверки компонентов

| ID | Проверка | Ожидаемый результат |
|---|---|---|
| LAC-IN-01 | Неизвестный `task_id` | HTTP 404 до оценивания |
| LAC-IN-02 | Пустая или пробельная строка | HTTP 422 |
| LAC-IN-03 | Файловая отправка без файлов | HTTP 400 |
| LAC-IN-04 | Клиент пытается передать иной максимальный балл | Значение не влияет на серверную конфигурацию |
| LAC-IN-05 | Любой файл превышает лимит или имеет неподдерживаемый формат | HTTP 413 или 415 соответственно; внешние вызовы для всего пакета ещё не выполнялись |
| LAC-IN-06 | В пакете первый файл допустим, последующий пуст | HTTP 400; внешние вызовы не выполнялись ни для одного файла |
| LAC-IN-07 | Длина текста превышает согласованный предел | HTTP 422 до оценивания; решение не заменяется обрезанным фрагментом |
| LAC-OCR-01 | Извлечение успешно | Запись непуста |
| LAC-OCR-02 | Фрагмент неразборчив | Неопределённость обозначена, формула не выдумана |
| LAC-OCR-03 | Варианты OCR существенно расходятся | Запущена дополнительная проверка по конфигурации |
| LAC-OCR-04 | Дополнительная проверка неуспешна, пригодный вариант есть | Использован вариант с сохранением неопределённости |
| LAC-OCR-05 | Все варианты пусты | Оценивание не запускается |
| LAC-SP-01 | Получены шаги | Их итоговые ID уникальны; безопасные дубликаты исходного ответа могут быть нормализованы |
| LAC-SP-02 | Получены шаги | Порядок соответствует исходной записи |
| LAC-SP-03 | Есть зависимости | Ссылки ведут на существующие предшествующие шаги |
| LAC-SP-04 | Разбор не дал пригодных шагов после допустимых резервных действий | Причина сохранена; оценивание продолжено без структурированного контекста по правилам |
| LAC-DC-01 | Неподдерживаемая форма | `unknown` |
| LAC-DC-02 | Получен `unknown` | Сам по себе он не снижает балл |
| LAC-DC-03 | Есть пропущенные и лишние корни | Они перечислены отдельно |
| LAC-DC-04 | Есть `confidence` узкой проверки | Он не представлен как вероятность правильности всей оценки |
| LAC-GR-01 | Состав критериев отличается от ожидаемого | Ответ отклонён; нет лишних, недостающих и повторных ID |
| LAC-GR-02 | Недопустимый статус критерия | Ответ отклонён |
| LAC-GR-03 | Пустое обоснование | Ответ отклонён |
| LAC-GR-04 | Невалидный JSON, попытки остались | Выполняется повторный вызов |
| LAC-GR-05 | Попытки исчерпаны | Возвращён технический результат компонента, а не оценка ученика |
| LAC-AR-01 | Вызван арбитр | Ему доступны обе оценки и общий контекст |
| LAC-AR-02 | Баллы A/B различаются | Арбитр вызван |
| LAC-AR-03 | Общий полный балл без неопределённости | Арбитр не вызван |
| LAC-AR-04 | Арбитр недоступен или его понижение заблокировано защитным правилом | Применена целевая политика BR-005 с явной предварительностью спорного результата |
| LAC-FP-01 | Формируется публичный ответ | Баллы согласованы между полями; происхождение преобразования внутреннего результата определено |
| LAC-FP-02 | Требуется ручная проверка | Есть причина и корректный статус создания задачи |
| LAC-FP-03 | Ответ возвращается ученику | Служебные ответы провайдера и промпты отсутствуют |
| LAC-FP-04 | Попытка сохранена | Промежуточные результаты доступны в её данных |

## Целевая интеграция и куратор

| ID | Дано / когда | Ожидаемый результат |
|---|---|---|
| PAC-P-01 | Результат требует куратора | Задача и состояние `needs_curator_review` сохранены согласованно |
| PAC-P-02 | Назначенный куратор подтверждает или меняет результат | Сохранены автор, время и новая версия; при изменении обязательна причина |
| PAC-P-03 | Результат изменён куратором | Исходная автоматическая оценка доступна и не перезаписана |
| PAC-P-04 | Принят валидный запрос LMS | После надёжного сохранения возвращены 202, `check_id`, `Location`; вычисление идёт асинхронно |
| PAC-P-05 | Эквивалентный запрос с прежним ключом, в том числе конкурентный | Создана одна проверка; возвращён её ID и актуальный статус |
| PAC-P-06 | Тот же ключ использован с другим телом | HTTP 409, прежняя проверка не изменена |
| PAC-P-07 | Клиент запрашивает чужую проверку | HTTP 404 без раскрытия данных |
| PAC-P-08 | Два куратора сохраняют несовместимые версии | Второе изменение отклонено с 409 |
| PAC-P-09 | Очередь недоступна после приёма запроса | Задание остаётся в надёжном хранилище; доставка повторяется, второй результат не создаётся |

## Проверка качества ИИ

Функциональные тесты подтверждают правила обработки; математическое качество проверяется отдельно.

1. Зафиксировать выборку и причины включения/исключения работ.
2. Получить экспертные оценки независимо от ответа системы и разрешить разногласия экспертов.
3. Зафиксировать версии модели, промпта, критериев и программных правил.
4. Разделить примеры настройки и контрольную выборку; учитывать повторяющиеся условия задач.
5. Запустить прежний и новый механизмы на одном контрольном наборе без изменения настроек внутри сравнения.
6. Посчитать совпадение баллов, ложные замечания, долю неоценённых работ, задержку и полную стоимость.
7. Зафиксировать выводы и подтверждённые случаи для регрессионных проверок.

## UAT

Ученик должен понять результат, отличие предварительной оценки от окончательной и следующий шаг после ошибки. Куратор должен видеть основания оценки и сохранять решение с историей изменений. Владелец LMS должен безопасно повторять запрос и получать доступный результат. UAT фиксируется протоколом: сценарий, вход, ожидаемый и фактический результат, версия, дата, участник и решение о приёмке.

Вход в приёмку: согласованы границы и критерии оценивания, подготовлены данные и версия контрактов. Выход: обязательные сценарии пройдены, отклонения разобраны, метрики рассчитаны, решение ответственного записано. Отсутствие согласованных числовых порогов не позволяет заявить выполнение таких порогов.

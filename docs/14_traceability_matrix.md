# Матрица трассировки требований

Матрица связывает потребность, требование, проектное решение и способ проверки. Фактический статус выполнения хранится в [матрице реализации](20_implementation_status.md). Ссылка на тест не означает выполнения более широкого целевого требования.

## Сквозной пользовательский сценарий

[UC-01 «Отправка решения текстом»](03_use_case_text_submission.md) раскрывает US-ST-02–US-ST-05 и цели BG-01, BG-03, BG-04. Основной ход связан с FR-001–FR-003, FR-005–FR-016, действующими C-01/C-08 и целевым C-11; расширение передачи куратору — с FR-P-003 и BR-P-001. Таблица в UC связывает конкретные шаги и ветви с существующими критериями приёмки. Файловые проверки и OCR в этот сценарий не входят.

## Проверка контракта UC-01

[Протокол P01–P08](12_api_verification_protocol.md) связывает ветви UC с запросами и фактическими результатами. P01 проверяет ответ и изоляцию истории; P02–P05 — вход и доступ; P06 — только ответ; P07 — представление предварительности; P08 — технические отказы. [Спецификация API](11_api_specification.md) связывает текущие C-01/C-08 с целевым C-11. Выполнение проверок текущего поведения не закрывает GAP-01, GAP-03 и GAP-06.

## Анализ данных на SQL

[SQL-блок](../sql/README.md) даёт способ расчёта M-QLT-01/M-QLT-02 в запросе 04 и отбора работ для разбора M-QLT-03 в запросе 06. Само расхождение баллов не доказывает ложное замечание. Проверки 01/02 поддерживают контроль качества и повторов данных; 03 — состава выборки; 05 — направления расхождений; 07 — времени до ручной проверки в смысле дат исходника.

В [протоколе SQL](../verification/sql-report.json) зафиксированы проверки на синтетических работах. Отдельно выполнен [анализ реальной выборки](15_dataset_analysis.md) из 9 042 работ: `ai_points` модели «Стобалльного репетитора» сравнивается с эталоном `curator_points`. Этот анализ не подтверждает выполнение требований PredelAI; версия сторонней модели и трактовка дат остаются ограничениями. Во [втором анализе](21_product_comparison.md) M-QLT-01/M-QLT-02 рассчитываются по эталону команды на общей выборке двух продуктов. [Модель данных и JOIN](../sql/comparison/README.md) реализованы и проверены. Эти расчёты сравнивают итоговые баллы; M-QLT-03 требует отдельной экспертной разметки комментариев.

## Связь с рисками

R-01/R-03 контролируются экспертной проверкой, а не только функциональными тестами. R-02 связан с FR-005; R-04 — с FR-012; R-05 — с FR-P-003; R-06 — с FR-P-007; R-07 — с требованиями доступа и публикации; R-08/R-12 — с ограничениями времени и стоимостью; R-09/R-10/R-13 — с версионированием; R-11 — с проверкой контрактов и этой матрицей.

## Правило сопровождения

При изменении требования обновляются его версия, связанные правила, контракты, диаграммы, критерии и статус проверки. Для пройденной проверки указываются вход, ожидаемый и фактический результат, дата и версия кода. Несогласованное либо не проверенное требование не помечается как выполненное.

# Метрики качества и эффективности

## Воспроизведённая сводка PredelAI

16 сентября 2026 года сводка пересчитана по предоставленному снимку на 165 строк. `true_score` — эталон, выставленный командой проекта для разработки; оценка куратора могла быть неверной. Авторство эталона подтвердил автор кейса. [Паспорт и парное сравнение продуктов](21_product_comparison.md) фиксируют источник и SHA-256. Версии запусков неизвестны; эти результаты не считаются проверкой текущей версии программы или независимой контрольной выборки.

| 13 | 72 | 42 |

Распределение разницы `PredelAI_score - true_score`: 0 — 104 работы; −1 — 5; +1 — 4; −2 — 2; +2 — 1. Отсюда MAE общей выборки: `(5 + 4 + 2×2 + 1×2) / 116 = 0,1293`.

49 из 165 строк не входят в сравнение — 29,7%. Для №13 сравнимы 42 из 72 строк. Причины пропусков неизвестны; пропуск не считается автоматически технической неудачей. Покрытие оценками показывается вместе с точностью. По одним номерам заданий нельзя приписывать результаты нынешнему маршруту программы.

Для прямого сравнения продуктов используются только 91 работа с обеими оценками и `true_score`: PredelAI — 83 совпадения (91,21%), сторонняя модель — 84 (92,31%); MAE обеих систем — 0,110. Разница составляет одну работу. [Четыре SQL-запроса](../sql/comparison/README.md) реализуют этот расчёт через нормализованные связи. 116 работ из таблицы выше — отдельная выборка PredelAI, которая не используется как знаменатель парного сравнения.

## Отдельный SQL-анализ новой выгрузки

Для предоставленной таблицы с полями `ai_points` и `curator_points` подготовлены и выполнены [семь SQL-запросов](../sql/README.md). Оценки `ai_points` и комментарии `ai_comment` относятся к модели «Стобалльного репетитора», что подтвердил автор кейса. По уточнению автора кейса от 16 сентября 2026 года оценка куратора используется как эталон. Это определение относится только к таблице на 9 042 работы. Во второй таблице на 165 работ эталон другой: `true_score`, разметка команды проекта. Подменять один эталон другим нельзя.

Запрос 04 рассчитывает совпадение и MAE по номеру задания; 05 разделяет завышения и занижения; 06 отбирает случаи для разбора. Запрос 07 измеряет время от отправки до регистрации ручной проверки. Оно не равно времени ответа ИИ или активному труду куратора. Для сопоставления с M-CUR-04 нужно отдельно подтвердить, что отправка соответствует созданию задачи куратора.

Выполненный анализ фиксированного снимка: **6 409 совпадений из 9 042, 70,88%; MAE 0,3751 балла**. По №13 — 71,09%, по №14 — 57,86%. В наборе 1 642 завышения и 991 занижение относительно эталона. Подробные знаменатели, исключения, контрольная сумма и ограничения — в [анализе датасета](15_dataset_analysis.md).

Это показатели сторонней модели на предоставленных работах, а не результаты PredelAI. Версия модели не предоставлена; №13 существенно преобладает. Числа PredelAI выше относятся к другой выборке и не доказывают улучшение относительно 70,88%. Временные интервалы рассчитаны по 9 020 строкам, но пока не являются подтверждённой характеристикой сервиса: временная зона и смысл событий требуют уточнения.

## Основная проблема и показатели

Главная бизнес-проблема — ложные замечания ученику. Поэтому основная связанная метрика — M-QLT-03. Совпадение итогового балла M-QLT-01 используется рядом с ней, а не заменяет её.

| ID | Метрика | Числитель / знаменатель или определение |
|---|---|---|
| M-QLT-01 | Совпадение балла с экспертом | Число совпадений / число работ с экспертной и числовой оценкой системы |
| M-QLT-02 | Средняя абсолютная ошибка | Среднее `abs(system_score - expert_score)` на сравнимых работах |
| M-QLT-03 | Доля ложных замечаний | Работы хотя бы с одним подтверждённым ложным замечанием / все работы с экспертной проверкой комментария |
| M-QLT-04 | Совпадение критериев | Совпавшие статусы / число критериев с экспертной разметкой |
| M-QLT-05 | Ошибочное автоматическое принятие | Автоматически принятые результаты, которые эксперт изменил бы / автоматически принятые результаты с независимой экспертной проверкой |
| M-QLT-06 | Обнаружение неоцениваемых работ | Отдельно precision и recall по экспертной метке невозможности оценки |
| M-QLT-07 | Покрытие оцениванием | Работы с числовой оценкой / все валидные работы, принятые в проверку |

Для каждого показателя сохраняются размер выборки и правила обработки пропусков. `null` не заменяется нулём при расчёте MAE. Доля неоценённых работ публикуется рядом с точностью.

## Стоимость

Исторические оценки: ИИ — около 7 ₽ за проверку; ручная проверка — около 10 ₽. Разница прямых оценок: 3 ₽, или 30%. Затраты на разработку, инфраструктуру и дополнительные ручные проверки в эту разницу не включены.

| ID | Метрика | Определение |
|---|---|---|
| M-COST-01 | Затраты на ИИ | Сумма стоимости всех вызовов одной проверки, включая повторы |
| M-COST-02 | Затраты по этапам | Распознавание, разбор, A, B, арбитр |
| M-COST-03 | Цена разногласия | Дополнительные затраты на арбитра и повторные вызовы спорных случаев |
| M-COST-04 | Стоимость согласованного с экспертом результата | Полные затраты на фиксированную сравниваемую выборку / число совпавших с экспертом результатов |

Условная модель: `C = 7 + 10 × r + c_other`, где `r` — доля работ, дополнительно оплачиваемых куратору по 10 ₽. При нулевых прочих расходах стоимость ниже 10 ₽ только при `r < 30%`. Это анализ чувствительности на исторических оценках, а не измерение экономии; фактическую цену повторной ручной проверки нужно подтвердить.

## План измерений

Зафиксировать версии данных, экспертов, промптов, моделей, критериев и программы. Сравнить варианты на одной независимой выборке; разделить результаты по номеру задания, типу входа, вызову арбитра и калибровке. Хранить автоматическую и ручную оценки раздельно. Не включать примеры настройки правил в независимую контрольную выборку без отдельной оговорки.

Числовые цели можно задать как проектные до исходного измерения. Владелец согласует порог, метод измерения проверяет достижимость. Неподтверждённые значения не обозначаются как достигнутые.

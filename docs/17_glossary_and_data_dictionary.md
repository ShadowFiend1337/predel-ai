# Глоссарий и словарь данных

## Терминология

В пояснениях используются русские названия. Английские имена сохранены только для совместимости с кодом и для устоявшихся технических обозначений.

| Термин | Значение / имя в реализации |
|---|---|
| Попытка | Сохранённая работа ученика с результатом; `Attempt` |
| Задача каталога | Условие, эталон и метаданные; `TaskCatalog` |
| Проверка | Процесс обработки решения; отдельное асинхронное задание — `CheckJob` |
| Оценщики A/B | Независимые вызовы моделей; `Grader A/B` |
| Арбитр | Дополнительная оценка спорного случая; в коде `adjudicator` |
| Калибровка | Программное изменение оценки по явному предметному правилу |
| Критерии оценивания | Набор условий и таблица баллов; `rubric` |
| Промпт | Инструкция языковой модели |
| LLM | Большая языковая модель |
| OCR | Распознавание текста на изображении |
| Разбор шагов | Структурирование решения; `StepParser` |
| Распознанная запись | Текст, полученный с изображения; `transcript_text` |
| Промежуточные результаты | Входы, выходы и сведения об этапах; `pipeline_artifacts` |
| Пояснения | Комментарий ученику и сведения об оценке; `feedback` |
| Признак ручной проверки | Необходимость участия куратора; не подтверждает создание задачи |
| Предварительная оценка | Полученный, но не утверждённый результат |
| Эталонная оценка | Результат независимой экспертной разметки по согласованным правилам |
| `unknown` | Недостаточно данных для конкретного программного вывода |
| `confidence` | Оценка уверенности конкретного компонента; не универсальная вероятность правильности |
| AS-IS / TO-BE | Текущее и целевое состояние процесса |
| API / REST / JSON | Интерфейс системы, подход к HTTP-взаимодействию, формат данных |
| BPMN / UML / ERD | Нотации процессов, моделей взаимодействия/состояний и связей данных |
| NFR / UAT / SLA | Требования к качеству, пользовательская приёмка, соглашение об уровне сервиса |
| Polling / webhook | Периодический запрос клиентом / уведомление от сервиса |
| Идемпотентность | Повтор эквивалентного запроса не создаёт дополнительный результат |

## Идентификаторы

| Контекст | Поле | Значение |
|---|---|---|
| Публичная отправка | `task_id` | ID конкретной задачи каталога, строка |
| Специализированное оценивание и разбор | `task_id` | Номер задания ЕГЭ строкой: `13`, `14`, `15` |
| Исторический набор оценки | `task_id` | Номер задания ЕГЭ |
| Попытка | `id` | ID сохранённой попытки |
| Целевая LMS-интеграция | `check_id` | ID асинхронного задания |

Совпадение имени поля не означает совпадение его предметного смысла. Номер задания и ID задачи не взаимозаменяемы.

| Поле | Тип БД | Допускает NULL | Значение |

| `statement_md` | Text | Нет | Условие |
| `reference_solution_md` | Text | Нет | Эталон; по умолчанию пустая строка |

Это значимый для кейса фрагмент модели, не перечень всех колонок. Вариант промпта вычисляется по метаданным, максимальный балл — по конфигурации.

## Физическая модель попытки — реализация

| Поле | Тип БД | Допускает NULL | Значение |
|---|---|---|---|
| `id` | String | Нет | PK; обычно генерируется UUID в строковом представлении |
| `task_id` | String | Нет | ID каталога, индекс; FK в текущей модели не объявлен |
| `user_id` | String | Да | FK на `users.id`; аутентификация API — отдельное ограничение |
| `text` | Text | Нет | Сохранённый текст решения |
| `file` | String | Да | Значение, переданное репозиторию; обработчик отправки записывает имя или объединённые имена файлов |
| `feedback` | JSON | Да | Пояснения и сведения об оценке |
| `mode` | String | Нет | Режим попытки |
| `score` | Float | Да | Сохранённый балл |
| `time_spent_sec` | Integer | Да | Время работы, если передано |
| `is_solved` | Boolean | Нет | Признак зачтённого полного решения |

Колонки `updated_at` и `max_score` в Attempt нет. Максимальный балл хранится внутри `feedback` и выводится через API. Целевые ограничения баллов не следует выдавать за CHECK-ограничения текущей БД.

## Соответствие представлений

| Предметное значение | API | БД / хранение |
|---|---|---|
| Текст решения | `solution_text` | `Attempt.text` |
| Условие | Серверный контекст `task_text` | `TaskCatalog.statement_md` |
| Эталон | Серверный контекст `reference_solution` | `TaskCatalog.reference_solution_md` |
| Максимальный балл | `max_score`, `feedback.max_score` | `Attempt.feedback.max_score` |
| Исходные файлы | Публичный ответ их не содержит | `pipeline_artifacts.uploads[].storage_path`; `Attempt.file` не гарантирует путь |

## Пояснения и оценка

`Feedback` содержит `spans_detail`, `checked`, `general_comment`, `comments`, `score`, `max_score`, `final_decision`, `needs_curator`, `review_required`, `review_reason`, `uncertainty_point`. Числовые поля и точка неопределённости допускают `null`; строковые и массивные поля имеют значения по умолчанию. Точный контракт — C-08 и JSON Schema.

`GraderResult` хранит балл модели `llm_score`, пересчитанный балл `score`, критерии, исходный ответ, число повторов, ошибку и метаданные. У арбитра используется та же структура. Проверка №13 хранит `details` строкой; `missing_roots` и `extra_roots` — массивами строк. Статусы математического вывода: `verified`, `failed`, `unknown`.

## Целевые сущности

| Сущность | Ключевые поля и ограничения |
|---|---|
| `CheckJob` | `id`, `lms_client_id`, `task_id`, `external_submission_id`, `idempotency_key`, `request_hash`, `submission`, `status`, `automatic_result`, `final_result`, `error`, `schema_version`, `version`, `created_at`, `updated_at`; уникальность `(lms_client_id, idempotency_key)` |
| `LayerResult` | `id`, `check_id`, `layer`, `execution_attempt`, `status`, `result`, `error`, `started_at`, `completed_at`, `latency_ms`, `schema_version`; уникальность `(check_id, layer, execution_attempt)` |
| `CuratorReview` | `id`, `check_id`, `assigned_to`, `status`, `automatic_score`, `curator_score`, `decision`, `reason_code`, `reason_text`, `version`, `completed_at`; уникальный `check_id` |
| `StatusHistory` | `id`, `check_id`, `event_id`, `from_status`, `to_status`, `actor_type`, `actor_id`, `version`, `reason_code`, `reason_text`, `changed_at`; уникальный `event_id` |
| `OutboxEvent` | `id`, `check_id`, `event_type`, `payload`, `published_at`, `created_at`; сохраняется с заданием одной транзакцией |

Автоматический и ручной результаты разделены. `automatic_score` допускает `null`, если надёжная оценка не получена. При завершении ручной проверки `curator_score` обязателен. Связи и допустимость пустых значений показаны в [ERD](../diagrams/erd.md). Операционные состояния и точный набор значений определены в [модели состояний](../diagrams/state_diagram.md).

## Целевые данные сайта: C-11

В отличие от сущностей LMS выше, эти записи принадлежат ученику сайта. Их поля и связи показаны в [ERD](../diagrams/erd.md), публичное представление — в [API 2.0](11_api_specification.md).

| Сущность | Назначение и ограничения |
|---|---|
| `AttemptV2` | Владелец и задача обязательны; исходник и подготовленный текст разделены; снимок условия, критериев и максимума; первоначальный и утверждённый результаты хранятся отдельно; версия для конкурентных изменений |
| `AttemptReview` | Уникальный `attempt_id`; обязательные причины передачи; куратор отсутствует до назначения; статус `pending`, `in_progress` или `completed`; ручной балл и время обязательны при завершении |
| `AttemptReviewEvent` | Событие изменения состояния, автор, причина, время и новая версия; уникальный `event_id` защищает от повторной записи события |

`solution_text` C-11 соответствует `source_text`; `review.id` — ID `AttemptReview`. `score`, `feedback` и `decision` берутся из окончательного результата, если он утверждён, иначе — из первоначального. `max_score` берётся из сохранённого снимка, `is_solved` вычисляется по окончательности и полному баллу. Данные технической ошибки не превращаются в `score=0`.

## Данные новой выборки для SQL

В новой предоставленной таблице используются `answer_id`, `ai_check_id`, `task_id`, `question_id`, `task_number`, `stud_id`, `max_points`, `ai_points`, `curator_points`, комментарии и даты отправки/проверки. `answer_id` обозначает ответ, `ai_check_id` — запуск проверки ИИ; эти значения нельзя смешивать с ID попытки сайта без сопоставления.

`curator_points` принят эталоном автором кейса 16 сентября 2026 года. `ai_points` и `ai_comment` относятся к модели «Стобалльного репетитора», по уточнению автора кейса; версия пока неизвестна. Словарь типов подготовленной временной таблицы, сохранение исходных значений дат и правила обработки пропусков — в [SQL-блоке](../sql/README.md). Исходные работы в репозиторий не включены; учебный набор синтетический. Отдельный [протокол реального анализа](15_dataset_analysis.md) содержит только агрегаты и методику.

## Данные сравнения продуктов на 165 работах

Поля сохранены на языке исходной таблицы: `task_id`, `task_text`, `solution_photo`, `their_ai_score`, `curator_score`, `reason_of_lowering`, `true_score`, `Diff`, `original_row_id`, `PredelAI_score`, `PredelAI_comment`, `Correct`, `predelAccuracity`.

`true_score` — эталонный балл, выставленный командой проекта для разработки; подтверждено автором кейса 16 сентября 2026 года. `curator_score` — исходная оценка куратора, которая могла быть неверной. `PredelAI_score` относится к PredelAI, `their_ai_score` — к модели «Стобалльного репетитора». Производные `Correct`, `Diff`, `predelAccuracity` не используются для расчёта: метрики пересчитываются по исходным баллам. `Diff` в исходном описании означает `true_score - their_ai_score`, поэтому не является ошибкой PredelAI.

`task_id` в этом источнике означает номер задания ЕГЭ, а не ID конкретной задачи. `original_row_id` повторяется, поэтому при подготовке назначается `work_id`, уникальный внутри снимка. [Аналитическая модель](../sql/comparison/README.md) определяет составные ключи оценок и эталонов. В снимке 51 различный текст условия. Выборка использовалась при разработке; её независимость от настройки не подтверждена. [Результаты](21_product_comparison.md) описывают общий знаменатель сравнения двух систем.

Исходные ссылки, работы и комментарии учеников не публикуются. В портфолио используются синтетические примеры и разрешённые агрегаты. Срок хранения рабочих данных и правила удаления требуют отдельного согласования.

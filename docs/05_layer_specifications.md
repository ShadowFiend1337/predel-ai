# Спецификация этапов проверки

Требования к этапам задают целевое поведение. Фактические структуры перечислены в [контрактах](06_json_contracts.md); состояние реализации — в [матрице](20_implementation_status.md). Критерии приёмки хранятся в одном [документе](08_acceptance_criteria.md), чтобы не дублировать идентификаторы и формулировки.

## Входы, выходы и ответственность

| Этап | Вход | Выход | Требования | Приёмка |
|---|---|---|---|---|
| 0. Приём и маршрутизация | C-01, аутентифицированный пользователь | Контекст задачи C-02 либо ошибка | FR-001–FR-003, FR-016 | PAC-01, PAC-02, LAC-IN-01–LAC-IN-07 |
| 1. Извлечение записи | Изображение, PDF с текстом или текстовый файл | Текст и сведения об извлечении C-03 | FR-004, FR-005 | PAC-03, LAC-OCR-01–LAC-OCR-05 |
| 2. Разбор шагов | Условие, запись, блоки текста и визуальные факты | `ParsedSteps` C-04 либо ошибка разбора | FR-006 | LAC-SP-01–LAC-SP-04 |
| 3. Программная проверка | Условие, решение, структурированные шаги | Факты геометрического аудита и проверка №13 C-05 | FR-007 | LAC-DC-01–LAC-DC-04 |
| 4. Оценщики A/B | Общий контекст, эталон и критерии | Две независимые оценки C-06 | FR-008, FR-009 | PAC-04, PAC-05, LAC-GR-01–LAC-GR-05 |
| 5. Арбитр | Контекст и обе оценки | Оценка C-07 или резервное решение | FR-010, FR-011 | PAC-06–PAC-09, LAC-AR-01–LAC-AR-04 |
| 6. Итоговые правила | Промежуточная оценка, математические и OCR-сигналы | Балл, его происхождение и окончательность | FR-011, FR-012 | PAC-13, PAC-14 |
| 7. Ответ и сохранение | Итоговое решение и промежуточные данные | Сохранённая попытка и C-08 | FR-013–FR-015 | PAC-10–PAC-12, LAC-FP-01–LAC-FP-04 |

## 0. Входные данные

Пустой или пробельный текст отклоняется до оценивания. Для файлов сначала проверяются наличие содержимого, размер и поддержка формата. Сервер получает задачу из каталога. Краткий ввод, состоящий только из ответа, обрабатывается по BR-012.

Конкретные поля, HTTP-коды и ограничения определены в C-01; требования к целевому результату при отсутствии оценки — в FR-011.

## 1. Извлечение записи

Для изображения выполняются коррекция ориентации, подготовка цвета, попытка устранения наклона, изменение размера и OCR. Несколько вариантов распознавания сравниваются; существенные расхождения требуют дополнительной проверки исходного изображения. Если дополнительная проверка недоступна, используется пригодный вариант с сохранением неопределённости.

Текстовый файл декодируется; PDF обрабатывается извлечением текстового слоя. Для сканированного PDF без текста текущая поддержка OCR-страниц не заявляется.

Целевой результат хранит исходник, выбранную запись и происхождение исправлений раздельно. Математическая правка не допускается в качестве неявной нормализации. Если все способы извлечения вернули пустой текст, оценивание не запускается.

## 2. Разбор шагов

Шаги получают уникальные ID, порядок, тип, отношение к предыдущему шагу, текст и ссылки на основания. Зависимости должны ссылаться только на существующие предшествующие шаги.

Текущий разбор включает нормализацию, устранение безопасных дубликатов и резервное восстановление шагов из явного текста. Эти действия отличаются от выдумывания решения. При непригодном результате после разрешённых попыток ошибка сохраняется, а оценивание может продолжиться без структурированных шагов.

## 3. Программные проверки

Геометрический аудит и проверка №13 имеют ограниченную область применимости. Результаты `verified`, `failed`, `unknown` относятся к математическому выводу проверки №13. Техническая ошибка этапа описывается отдельно и не обозначает неверное решение ученика.

Поле `confidence` узкой проверки не является вероятностью правильности всей оценки. Пропущенные и лишние корни фиксируются отдельно.

## 4–5. Оценщики и арбитр

Каждый оценщик получает одинаковые условие, решение, эталон и критерии, не получая ответ второго оценщика. После ответа выполняются проверка структуры, программный пересчёт и внутренняя калибровка. Арбитр использует обе оценки и тот же предметный контекст.

Целевая валидация отвергает повторяющиеся/неизвестные критерии, недопустимые статусы и пустые обоснования. Число повторных попыток ограничено. Текущие отклонения от строгой валидации вынесены в матрицу реализации.

Вызов арбитра, защита общего результата и резервные ветки определены в BR-005. Эта спецификация не вводит альтернативной таблицы решений.

## 6. Итоговые правила

Итоговая калибровка следует после обработки A/B и арбитра. Существенная неопределённость исходных данных учитывается отдельно. Целевая запись изменения включает `rule_id`, версию, входной и выходной баллы, основание и изменение окончательности результата. Пример такой записи является целевой моделью, а не существующим единым объектом в коде:

```json
{
  "rule_id": "EXAMPLE_RULE",
  "rule_version": "1.0",
  "score_before": 1,
  "score_after": 2,
  "reason": "Синтетический пример подтверждённого программного правила",
  "result_status_before": "provisional",
  "result_status_after": "provisional"
}
```

## 7. Формирование ответа и сохранение

Баллы внутри ответа и на верхнем уровне должны совпадать. `is_solved` определяется по BR-009. Отсутствующий балл представлен `null`, предварительный результат не выдаётся за окончательный. Сообщение о передаче куратору зависит от факта создания задачи.

Попытка и JSON промежуточных результатов сохраняются вместе. Успешный ответ формируется после фиксации транзакции; сохранение исходного файла и обновление статистики пользователя не следует автоматически считать частью той же транзакции БД.

## Политика отказов — целевые требования

| Ситуация | Реакция |
|---|---|
| Неверный запрос или неизвестная задача | Ошибка до вызовов ИИ |
| Пустое извлечение | Остановить оценивание, предложить другой вход |
| Непригодный результат разбора | Записать ошибку; продолжить без шагов только по допустимому сценарию |
| Неподдерживаемая программная проверка | `unknown`, без самостоятельного снижения балла |
| Невалидный ответ оценщика | Ограниченное число повторных попыток |
| Один оценщик недоступен | Предварительный результат и ручная проверка |
| Оба оценщика недоступны | Отсутствующая оценка и контролируемая техническая ошибка |
| Требуемый арбитр недоступен | Предварительный результат и ручная проверка |
| Ошибка программного правила | Сохранить предыдущий результат как предварительный и причину отказа правила |
| Ошибка сохранения | Не возвращать успешный ответ о сохранённой попытке |

В публичной ошибке не передаются тексты исключений провайдера, секреты и служебные промпты. Детали диагностики связываются с запросом по внутреннему идентификатору.

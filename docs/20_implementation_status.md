# Состояние реализации и основания проверки

Первичная проверка: 14 сентября 2026 года. Документация и повторный запуск тестов: 15 сентября 2026 года. Источник — предоставленная папка `predel` рядом с кейсом. Это техническое приложение: основные требования описывают целевую систему, а здесь фиксируется её соответствие существующему коду.

## Статусы

- **Реализовано** — механизм прослежен в коде; границы проверки указаны отдельно.
- **Частично** — есть основа, но целевая гарантия обеспечена не полностью.
- **Целевая модель** — спроектировано, реализация не подтверждена.
- **Проверено тестом** — конкретный существующий тест пройден; это не подтверждение всех сценариев или качества ИИ.

## Соответствие требований

| Требования | Статус | Основание и границы |
|---|---|---|
| FR-001 | Реализовано | `submit.py`, `_STANDALONE_EGE_VARIANTS`, определение варианта промпта |
| FR-002 | Реализовано в границах C-01 | Приём текста, изображений и файлов; PDF только с текстовым слоем |
| FR-003 | Частично | Поля, задача и каждый файл проверяются; все файлы пакета заранее не проверяются, OCR первого файла может предшествовать обнаружению ошибки следующего. Слишком длинный текст обрезается |
| FR-004 | Реализовано | Несколько вариантов OCR, данные распознавания и конфликтов; качество требует экспертной оценки |
| FR-005 | Частично | Есть математические замены в `_repair_standalone_ege_text`, в том числе для введённого текста; требуется разделение исходника и подтверждённой правки |
| FR-006 | Реализовано | Разбор, нормализация, резервное восстановление явных шагов и продолжение без контекста при отказе |
| FR-007 | Реализовано в ограниченной области | Геометрический аудит и проверка №13; нет универсального решателя |
| FR-008 | Реализовано | Независимые вызовы, настройка параллельности |
| FR-009 | Частично | Проверяются структура, обязательные критерии и статусы; пустые обоснования и повторные ID принимаются, лишние критерии удаляются |
| FR-010 | Частично относительно целевой политики | Точный существующий алгоритм описан BR-005; целевая маркировка спорного результата требует изменения |
| FR-011 | Частично | Ветви отказов есть; отсутствие оценки представляется нулём с признаком ручной проверки, а операционной очереди нет |
| FR-012 | Частично | Калибровка выполняется до сравнения и после арбитра; единая запись ID/версии/баллов до и после требует формализации |
| FR-013 | Частично | Основная схема ответа есть; исключения согласованности и окончательности перечислены ниже |
| FR-014 | Реализовано для записи Attempt | Попытка и её JSON сохраняются одной операцией вставки с фиксацией транзакции; исходный файл и статистика пользователя не входят автоматически в эту атомарность |
| FR-015 | Реализовано для сохранения попытки | Репозиторий фиксирует транзакцию до возврата результата; полный отказоустойчивый сценарий проверяется отдельно |
| FR-016 | Реализовано в текущем процессе | На изолированном стенде P01 проверяет изоляцию истории, P03 — отсутствие/повреждение JWT, P05 — срабатывание ограничителя. Распределённая нагрузка и реальная БД не проверялись |
| FR-P-001–FR-P-007 | Целевая модель | Внешний API, очередь, куратор и история ручных решений не реализованы в предоставленном коде |
| UC-01 | Целевая модель | [Отправка решения текстом](03_use_case_text_submission.md): основной ход, альтернативы, ошибки и постусловия. Условия поведения сайта требуют отдельной приёмки; передача куратору зависит от реализации ручного процесса |
| C-11 | Целевая модель | [API сайта 2.0](11_api_specification.md) и связь `AttemptV2` → `AttemptReview` спроектированы; проверены структура и примеры. Маршрутов v2 в backend нет |

## Изменения, необходимые для целевых гарантий

| ID | Фактическое поведение | Целевое изменение | Приёмка |
|---|---|---|---|
| GAP-01 | До оценивания применяются математические замены и обрезание слишком длинного текста | Не менять исходную математику без подтверждения; хранить исходник отдельно, превышение длины отклонять | PAC-15, LAC-IN-07 |
| GAP-02 | Валидатор принимает пустой `reason` и повторный ID критерия | Проверять непустоту, уникальность и точный состав критериев | LAC-GR-01, LAC-GR-03 |
| GAP-03 | Отказ моделей может дать 0 и сообщение о передаче куратору | Разделить техническую неудачу, предварительную оценку и подтверждённое назначение | PAC-08, PAC-09, PAC-P-01 |
| GAP-04 | При недоступном арбитре общий балл либо минимум при разнице в 1 балл принимается без куратора; понижение арбитром общего результата может быть проигнорировано автоматически | Сохранять спорный результат как предварительный и создавать ручную проверку | LAC-AR-04 |
| GAP-05 | OCR-маршрутизация может заменить публичный балл на 0 | Сохранить отсутствие или предварительность оценки без математического обнуления | PAC-14 |
| GAP-06 | В ветке «только ответ» `feedback.score=0`, а верхние `score/max_score` остаются `null` | Согласовать поля и предметный отказ | PAC-16 |
| GAP-07 | Есть поэтапные ограничения времени, нет единого ограничения всего синхронного запроса | Определить общий предел и поведение при его превышении | NFR-PERF-01 |
| GAP-08 | Нет единой версии всех критериев, промптов, моделей и правил вместе с результатом | Сохранять версии и происхождение изменения | NFR-MNT-02, PAC-13 |
| GAP-09 | Нет операционной очереди куратора и внешнего асинхронного API | Реализовать целевую интеграцию и ручной процесс | PAC-P-01–PAC-P-09 |
| GAP-10 | В одной из веток техническое исключение включается в текст публичного пояснения | Публичный безопасный код/текст; подробности только в служебной диагностике | NFR-SEC-03 |
| GAP-11 | Файлы проверяются и извлекаются последовательно; ошибка позднего файла может возникнуть после платного OCR раннего | Проверять допустимость всего пакета до внешних вызовов | LAC-IN-05, LAC-IN-06 |

Эта документационная доработка не изменяет программную реализацию перечисленных пунктов.

## Проверка HTTP-контракта UC-01

[Протокол P01–P08](12_api_verification_protocol.md) фиксирует **38 HTTP-запросов и 74 пройденные проверки Postman**. Использованы настоящие обработчики, JWT и ограничитель, а каталог, сохранение и весь механизм оценивания заменены синтетическими данными. Подтверждены условия ответа и побочные действия на этом стенде, включая обрезание длинного текста, расхождение баллов при ответе без решения и технический ноль. Это не выполнение целевых требований и не проверка реальной БД или моделей.

Две OpenAPI-спецификации структурно корректны; 36 примеров соответствуют схемам. Проверяющие модели приняли 10 допустимых примеров и отклонили 25 недопустимых. Коллекции согласованы со схемами; скрипты обеих коллекций синтаксически корректны. Целевая коллекция HTTP-запросами не исполнялась: сервер v2 не реализован. Контрольные суммы и результаты — в [отчёте](../verification/uc01-api-report.json).

## Проверка SQL-блока

16 сентября 2026 года выполнены [семь SQL-запросов](../sql/README.md) в PGlite 0.5.8 — PostgreSQL-движке в памяти. На восьми синтетических работах и дополнительных граничных случаях пройден **21 сценарий проверки**: расчёты, пропуски, недопустимые баллы, даты, дубли, один элемент и пустая выборка. Среда, результаты и контрольные суммы сохранены в [протоколе](../verification/sql-report.json).

К рабочей БД приложение проверки не обращается. Отдельно семь запросов выполнены в PGlite на фиксированном реальном снимке из 9 042 работ. Эталон — `curator_points`, модель — «Стобалльный репетитор», а не PredelAI. [Результаты](15_dataset_analysis.md) и [протокол](../verification/dataset-analysis-report.json) фиксируют 70,88% совпадений, причины исключений и SHA-256. Сравнение баллов охватывает все строки; расчёт времени по 9 020 строкам условен до уточнения временной зоны. Дальнейшие измерения отражены в [направлениях развития](16_product_roadmap.md).

Дополнительно выполнены [четыре SQL-запроса сравнения продуктов](../sql/comparison/README.md) на снимке из 165 строк с эталоном команды `true_score`. На общей выборке 91 работа получены 83 совпадения PredelAI и 84 сторонней модели. Проверены семь синтетических сценариев: пропуски, нулевые баллы, приоритет эталона команды, уникальность оценок, внешние ключи и пустая выборка. Метрики независимо пересчитаны; [протокол](../verification/comparison-analysis-report.json) содержит агрегаты и контрольные суммы.

## Проверка документации

Проверены 32 Markdown-документа, 243 локальные ссылки и 15 JSON-примеров: ошибок ссылок и JSON-синтаксиса не обнаружено. Четыре примера проверены по структурам `AttemptIn`, `ParsedSteps`, `AttemptOut` и `Task13VerifierResult`; две JSON Schema совпадают с моделями исходного кода. Проверена определённость 255 идентификаторов требований и связанных артефактов. В UC-01 проверены нумерация 13 основных шагов и ссылки на 14 альтернативных и ошибочных ветвей; пример запроса соответствует `AttemptIn`, HTTP-часть текущего маршрута проверена на изолированном стенде; интерфейс и полный целевой сценарий не проверялись. Для BPMN проверены XML, ссылки узлов и потоков, границы процесса и координаты; SVG-превью просмотрено визуально. Целевые структуры не выдаются за ответы действующего API. Предоставленный снимок на 165 строк пересчитан по первичным данным; авторство `true_score` подтверждено автором кейса. Версии запусков и независимость выборки остаются ограничениями.
